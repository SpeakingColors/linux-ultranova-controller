# Roadmap: UltraNova controller

Editor for the Novation UltraNova, in the look of the Novation editor.

## Done
- [x] Plugin skeleton: parameter map from the manual, CC and NRPN send/receive, host automation, cat-ui look, CI on three systems
- [x] Release packaging: installers (Windows, macOS, Linux Flatpak extension), uninstallers and PDF manual built by the release workflow (test builds, not tested on real machines)

- [x] Full NRPN map (374 entries plus ClockBPM 14 bit), generated by tools/gen_map.py
- [x] Backend rules from the source: nrpnMSB reset, 14 bit data, packed bit helpers, outgoing queue, device inquiry parser
- [x] Device model and tests for every map entry, fuzz runs

## Next
- [ ] Device inquiry in the plugin (Identity request on connect, show what answered); the parser exists, the host MIDI path for SysEx still has to be proven
- [ ] Packed specials 0:122 to 0:127 and the spare entries once Novation's Patch & Global spec is found
- [ ] Real labels and ranges for choice parameters (waveforms, filters, FX types, mod sources and destinations)
- [ ] The real window from the approved mockup instead of the parameter list (the list still shows stand-in rows)
- [ ] Test every map entry on the real device and flip it to verified (`hw` column in map/params.csv)
- [ ] Test the VST3 in Bitwig and Studio One on Linux
- [ ] Two-CC controls: find out which CC is the coarse one on the device

- [ ] Wave table names and the CC value to name mapping (the MIDI doc gives CC 19, 29 and 41 for the oscillator waveforms but no value list)
- [ ] Real MIDI I/O behind the mockup controls
- [ ] Librarian page with backup and restore
